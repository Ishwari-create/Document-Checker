Receipts in layouts it was never built for

The test set above uses the three layouts the extractor was written against, so it flatters the extractor. To see what happens with a bank it has never seen, two further sets of 8 receipts were made in new layouts after the code was written. The first run on each is the honest number; set 1 was then used to widen the label wording, so only set 2 is still unseen.

Unseen layout 2 (8 receipts, 2 scans)2 of 4 defects caught, 1 correct scan wrongly failed (amount misread), 0 defective receipts passed {% set h=hold.holdout2 %}{{ h.defects_caught_by_right_rule }} defects caught, {{ h.clean_wrongly_failed }} wrongly failed, {{ h.defective_passed_as_clean }} defective passed, {{ h.clean_sent_to_review }} correct sent to review. Label wording not tuned; the scan rule below was added after this run.

What this shows: on unfamiliar wording the checker mostly says "I could not read this, officer please look" rather than guessing. It has not yet passed a defective receipt. Since that run, an amount read from a scan can no longer fail a receipt unless the figures and words agree. Onboarding a new bank's wording is a change to config/field_labels.yaml.
